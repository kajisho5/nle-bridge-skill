# Changelog

## Unreleased

- Multicam sources for the editor (roadmap step 15, ADR-011): ffmpeg-skill's `multicam.py --json` result is an input of `export`, `conform`, `diff` and `import`. The cameras become the angles of one multicam at their sync offsets (in frames) and the switch list the initial cut: in FCP7 XML each cut is a clipitem holding the multiclip with its angle active, in OTIO a Stack with one track per angle (only the active one enabled), in the EDL the plain switched cut (`MULTICAM_NOT_EXPORTED`). The readers take both back (`multicam` on the timeline and on each cut); `diff` reports each angle's offset and the cuts the editor switched to another angle (`multicam.angle_switches`). Drift correction is not carried (`MULTICAM_DRIFT_NOT_EXPORTED`), the sound is camera 0's (`MULTICAM_AUDIO_ASSUMED`), and no NLE has opened the multiclip yet (`MULTICAM_AS_MULTICLIP`). `LAYER_POSITION_NOT_EXPORTED` (step 14) is now a loss code, so `--strict` refuses it.
- Graphics layers on upper tracks (roadmap step 14, ADR-010): a plan's `layers` (manifest paths, manifests or layers, `nle-bridge/layers@1`: id, file, start / end, box, the file's size and length, alpha) puts each alpha file on its own video track above the picture, in OTIO and FCP7 XML (`TRACK_NOT_EXPORTED` in the EDL). `conform` lists the layer files in `relink.json` (with `layer`) and `manifest.json` and copies them with `--copy-media`; `diff` lists each layer's pair under `layers` (`summary.layers_changed`), and `--timeline-out` keeps what each layer is. A file smaller than the frame is centred by the NLE (`LAYER_POSITION_NOT_EXPORTED`; the box is kept in OTIO metadata and relink.json). The producers' manifests are not built yet: the shape is handed over in `docs/handover-layer-manifest.md`. No new CLI flag (the contract's `argv` is unchanged).
- Timelines written by auto-editor (roadmap step 13, ADR-009): `import` and `diff` read the FCP7 XML auto-editor exports for Premiere. Fixtures made by auto-editor 29.3.1 (Unlicense; sha256-pinned release binary, regenerated and compared byte for byte in CI) on a clip with two silences at 29.97 NDF and 25 import with exactly the cut list auto-editor reports, and `diff` against a plan built from those cuts reports no change. The FCP7 XML reader now names what it does not keep: `LABEL_NOT_IMPORTED` (clip labels), `LINKS_NOT_IMPORTED` (picture-sound links), `AUDIO_FORMAT_NOT_IMPORTED` (sequence sample rate / depth), `CHANNEL_TRACKS_NOT_IMPORTED` (one track per channel), `COMPOSITE_NOT_IMPORTED` (a composite mode other than normal) and `PIXEL_ASPECT_NOT_IMPORTED`. No auto-editor code is used at run time.
- Media start timecode (roadmap step 12, ADR-008): ffmpeg-skill 3.0.0's `probe` reports `timecode: {value, drop_frame, source}` (this repository's hand-over), and nle-bridge now takes it for every media file the plan gives no start for: plans, render projects and agent IRs alike, in `export`, `conform` and `diff`. `relink.json` has `facts_from.start_timecode` / `facts_from.drop_frame` `"ffmpeg-skill probe"`, a per-file `drop_frame` and `start_timecode_source`, and the OTIO / FCP7 XML / EDL source timecodes start there. The plan's value wins when both exist and differ (`START_TIMECODE_MISMATCH`); a label that cannot be used is `START_TIMECODE_UNREADABLE`. The ffmpeg-skill dependency's `version_range` is `>=2.0.0 <4.0.0`: 2.x (no `timecode`) still works and the start stays not known, with `start_timecode_note` saying why and `doctor` noting it. Each file is probed once per run. The FCP7 XML reader labels a file's start with its own `<displayformat>` (DF), not always non-drop. CI's integration job runs against ffmpeg-skill v3.0.0, v2.24.1 and main.

- Premiere stereo pairs (roadmap step 11, ADR-007): `diff` folds Premiere's per-channel copies of a stereo clip (A1 + A2, or an EDL `AA` event) back into one clip before pairing tracks, so they are no longer reported as added and later audio tracks pair correctly; `channels_folded`, `channel_tracks`, `summary.channel_clips_folded`. A copy the plan has is compared; a copy edited alone is reported as added (`channel_of`). The OTIO and FCP7 readers keep returned ids unique (`<id>@<track>`). `--timeline-out` keeps one clip per stereo source.
- Cross dissolves (roadmap step 10, ADR-006): `--dissolves` on `export`, `conform`, `diff` and `import` writes each plan `transition_in` as a cross dissolve centred on the cut, in OTIO (Transition), FCP7 XML (transitionitem) and CMX 3600 (`D` event), the shape ffmpeg-skill writes; the cut points stay put. Dissolves that cannot be written are named (`TRANSITION_NOT_EXPORTED`, `TRANSITION_AS_DISSOLVE`, `TRANSITION_OFF_CENTRE`). The readers take dissolves back from all three formats and `diff` reports a `transition` change; a render project's fade is laid out as ffmpeg-skill lays it; `relink.json` names the handles. Without the flag nothing changes.
- Live control by reuse (roadmap step 9, ADR-004): `docs/live-control.md` pins davinci-resolve-mcp 4.17.0 and premiere-pro-mcp 1.27.0 (both MIT), with their install commands, a chat-app config and the switches that keep script tools, telemetry and self-update off. No server code is used or copied.
- Media start timecode (roadmap step 12, ADR-005): not read with ffprobe here; a hand-over to ffmpeg-skill `probe` (`docs/handover-media-start-timecode.md`). Closed by ffmpeg-skill 3.0.0 and the entry above.

## 0.1.0 - 2026-10-31

First release (roadmap steps 1-6).

- `nle-bridge export`: a plan (`nle-bridge/timeline@1`, video-production-agent's project IR, an ffmpeg-skill render project, or an OTIO / FCP7 XML / EDL) as OpenTimelineIO, FCP7 XML (xmeml 4, for Premiere) and CMX 3600 EDL, plus an SRT sidecar for captions. Whole frames at exact rates (23.976 = 24000/1001, 29.97 and 59.94 drop-frame or not); seconds rounded to the nearest frame, ties to even, like ffmpeg-skill. Effects, speed changes, titles, transitions and every format-specific loss are warnings naming the item; `--strict` exits 5 before writing.
- Beat grids (`--beats`): ffmpeg-skill `scenes --beats` output, a `beat_grid`, or `nle-bridge/beatgrid@1`; bar heads RED `Bar N`, other beats CYAN `Beat N.b`; bars ASSUMED every N beats when the grid states none.
- `nle-bridge conform`: timelines, the plan as JSON, `relink.json` (path, exists, size, sha256, start timecode, length, fps, picture size, ranges used, and where each fact came from: ffmpeg-skill `probe` when found) and `manifest.json`; deterministic zip; `--copy-media`.
- `nle-bridge diff`: the editor's returned OTIO / FCP7 XML / EDL against the plan: clips changed / added (`split_from` a razor cut) / removed, cut points moved in frames, markers changed, and with a beat grid each cut's offset from the nearest beat; `--timeline-out` writes the returned cut as the next plan.
- `nle-bridge import`, `contract` (Velisa registry shape, validates against `capability_contract.schema.json`), `doctor`.
- Tested: timecode anchors and every-frame DF round trips; every format read back identical at six rates; opentimelineio and its FCP7 / CMX 3600 adapters read the same cut; ffmpeg-skill's own `render --export-timeline` files read back cut for cut. Not tested: import into a real Premiere or Resolve.
